1. Executive Overview & DFD Architecture Scope

This document serves as the formal engineering Data Flow Diagram (DFD) specification for the StaffO Enterprise Multi-Tenant ERP System. The architecture facilitates rigorous multi-tenant data boundary isolation, granular role-based access control (RBAC), end-to-end HRM Employee 360 profile management, real-time hardware biometric attendance capture via the ZKTeco ADMS push protocol, leave quota workflows, and weekly cafeteria meal scheduling.

4. Detailed Process Specifications

Process 1.0: Tenant Resolution & RBAC Authorization Engine Process 1.0

Purpose: Validates incoming HTTP requests, resolves tenant from X-ORG-ID header, authenticates Sanctum bearer tokens, and verifies user permissions through closure trees.

Inputs: HTTP Request Headers (Authorization, X-ORG-ID), Login Credentials (email, password)
Data Stores Accessed: D1: Multi-Tenancy, D2: RBAC Matrix, D7: Security & Users
Outputs: Authenticated User Session, Granted Permissions List, Access Denied (403) Exceptions
Process 2.0: HRM Employee 360 Lifecycle Management Process 2.0

Purpose: Handles employee onboarding, biometric ID mappings, reporting lines, supervisor chains, and manages 6 child sub-profile tables.

Inputs: Employee demographics, National ID, Bank accounts, Education records, Family details, Uploaded docs
Data Stores Accessed: D3: Employee 360 Store (hrm_employees, educations, families, etc.)
Outputs: Complete Employee 360 payload, Organogram tree structure, Profile audit logs
Process 3.0: Realtime ADMS Ingestion & Shift Evaluation Process 3.0

Purpose: Listens on ADMS push HTTP endpoints (/iclock/cdata), decodes multi-line biometric packets, inserts raw logs, and applies shift evaluation rules (grace period, late flags, overtime).

Inputs: Hardware push strings: SN=BIOTERM01\n102\t2026-08-19 08:58:12\t1\t1
Data Stores Accessed: D4: ADMS Attendance Store (adms_devices, raw_attendances, work_shifts)
Outputs: HTTP 200 OK ACK to device, Daily evaluated attendances, Attendance discrepancy alerts
Process 4.0: Leave Quotas & Multi-Tier Workflow Engine Process 4.0

Purpose: Initializes yearly quotas per leave type, validates balance deductions, skips public holidays/weekends, and routes approval requests up the manager chain.

Inputs: Leave application date range, Leave type ID, Employee ID, Manager decision (Approve/Reject)
Data Stores Accessed: D5: Leave & Holiday Store (hrm_holidays, leave_balances, leave_applications)
Outputs: Balance decrement transactions, Approval status notifications, Calendar block updates
Process 5.0: Cafeteria Menu Scheduling & Booking Verification Process 5.0

Purpose: Enables cafeteria chefs to schedule weekly meal menus, enforces reservation cutoff windows, generates meal redemption tokens, and verifies consumption at counters.

Inputs: Weekly menu details, Staff lunch selection, Barcode scan at cafeteria counter
Data Stores Accessed: D6: Cafeteria Meals Store (hrm_weekly_meals, hrm_employee_meal_selections)
Outputs: Meal Token QR payload, Token redeemed validation response, Kitchen headcount forecast
Process 6.0: System Telemetry, Security & Field-Level Audit Process 6.0

Purpose: Monitors API gateway response latency, tracks login failures to prevent brute force, and captures before/after JSON diffs on model mutations.

Inputs: Request execution duration, Client IP, Eloquent model mutation events (created, updated, deleted)
Data Stores Accessed: D7: Security & Audit Store (audit_logs, user_login_attempts, password_histories)
Outputs: Security violation triggers, Historical field audit trails, Live gateway telemetry charts
